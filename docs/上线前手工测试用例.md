# 上线前手工测试用例

## 1. 使用说明

本文档用于把《上线前任务清单.md》《需求文档.md》《用户故事.md》中的 V1 范围转成可执行的手工测试用例。执行时优先跑 P0，再跑 P1；P2/P3 可根据上线时间决定是否完整覆盖。

### 1.1 测试目标

先保证核心业务闭环可用，再保证关键异常场景不炸：

- 游客能浏览公开内容，但不能执行登录态操作。
- 用户能完成注册、登录、发帖、评论、点赞、收藏、关注。
- 用户能购买资源帖，金币、交易记录、隐藏内容权限保持一致。
- 用户能发布悬赏帖、回答、采纳答案，冻结金币和奖励发放保持一致。
- 管理员能完成基础后台管理、内容下架、用户管理、资产审计。
- 越权、重复提交、余额不足、下架内容等高风险场景必须被拦截。

### 1.2 通用测试环境

| 项目 | 建议值 |
| ---- | ------ |
| 前台地址 | `http://localhost:8080/` 或当前部署地址 |
| API 健康检查 | `/api/v1/health` |
| 浏览器 | Chrome 最新稳定版 |
| 终端 | PC 必测，移动端至少做核心页面冒烟 |
| 测试账号 | 游客、普通用户 A、普通用户 B、管理员 |
| 数据要求 | 每轮测试使用独立测试用户和可识别标题，避免混淆历史数据 |

### 1.3 测试账号建议

| 角色 | 账号建议 | 用途 |
| ---- | -------- | ---- |
| 游客 | 不登录 | 浏览公开内容、验证受限操作拦截 |
| 用户 A | `test_user_a` | 发帖人、资源卖家、悬赏提问者 |
| 用户 B | `test_user_b` | 买家、答主、评论者、举报者 |
| 管理员 | `test_admin` | 后台审核、下架、用户管理、资产审计 |

### 1.4 缺陷优先级

| 优先级 | 判定标准 |
| ------ | -------- |
| P0 | 核心流程无法完成、数据错误、重复扣费、越权、安全问题、系统崩溃 |
| P1 | 严重影响主要功能体验，但存在绕过方式 |
| P2 | 不影响核心闭环，影响少量用户或次要路径 |
| P3 | 文案、样式、轻微体验问题 |
