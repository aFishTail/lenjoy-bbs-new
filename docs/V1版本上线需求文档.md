# V1 版本上线需求文档

## 1. 文档说明

本文档用于汇总 Lenjoy BBS V1 版本上线范围内的功能需求，作为上线前范围确认、测试验收、缺陷优先级判断和发布决策的依据。

本文档基于仓库内现有《需求文档.md》《用户故事.md》整理，不替代完整 PRD；它更偏向上线确认清单，重点回答：

- V1 要上线哪些功能。
- 每个功能属于哪个业务模块。
- 功能的核心概述和上线验收要求是什么。

## 2. V1 上线目标

V1 版本目标是交付一个可用的社区产品基础闭环：

- 用户可以注册、登录、浏览、发帖、评论、点赞、收藏、关注。
- 用户可以通过金币购买资源帖，并查看购买记录和金币流水。
- 用户可以发布悬赏帖、回答悬赏、采纳答案，并完成金币冻结、发放和回答内容可见性控制。
- 管理员可以进行基础内容治理、用户管理、资产审计和后台运营。
- 系统具备上线所需的基础安全、稳定性、数据一致性和可观测能力。

## 3. V1 明确不包含

以下能力不进入 V1 上线范围，避免上线前范围失控：

- 第三方支付接入。
- 用户提现与收益结算。
- 自动分账。
- 复杂推荐算法。
- 私信系统。
- 高级搜索和复杂筛选。
- 用户等级体系。
- 新手任务、签到、积分活动等运营玩法。

| V1-POST-002 | 帖子详情 | 帖子与内容 | P0 | 用户可以进入帖子详情查看标题、正文、作者、时间、状态和互动数据。 | 详情数据与列表一致。 | 普通帖详情正常；资源帖公开内容正常；不存在或已下架帖子有合理提示。 |

| V1-NFR-004 | 性能与压力测试 | 非功能与上线保障 | P0 | 上线前验证首页、列表、详情、登录、发帖、购买等核心链路能承受预估用户量。 | 资源购买并发场景必须保证资产一致性。 | 核心链路无持续 5xx；P95 响应时间和错误率满足上线标准。 |
| V1-NFR-005 | 日志与请求追踪 | 非功能与上线保障 | P0 | 系统记录关键请求、错误和业务事件，支持上线后排查问题。 | 日志不能明文输出密码等敏感信息。 | 登录失败、发帖、购买、后台操作可按请求 ID 追踪。 |
| V1-NFR-006 | 数据备份与回滚条件 | 非功能与上线保障 | P0 | 上线前确认数据库备份和回滚条件。 | 无备份不建议上线。 | 备份时间、位置、负责人明确；登录、发帖、购买异常时有回滚策略。 |

## 5. 上线优先级说明

| 优先级 | 含义 | 上线处理原则 |
| ------ | ---- | ------------ |
| P0 | V1 核心闭环或上线安全底线 | 必须完成并验收通过，否则不建议上线 |
| P1 | 上线前建议完成的可用性和运营支撑能力 | 原则上完成；如延期必须有明确绕过方案 |
| P2 | 增强体验或运营分析能力 | 可上线后迭代，不阻塞 V1 发布 |

## 6. V1 上线判定

建议满足以下条件后再发布 V1：

- P0 功能全部完成并通过测试。
- P0 缺陷清零。
- P1 缺陷已修复或有明确放行说明。
- 核心手工测试和关键 E2E 测试通过。
- 资源购买、悬赏采纳、金币流水没有资产一致性问题。
- 管理后台具备处理用户、帖子、资产审计的基础能力。
- 压力测试和容量验证通过，或有明确限流、降级和放行说明。
- 上线数据、日志、备份、回滚条件已确认。
