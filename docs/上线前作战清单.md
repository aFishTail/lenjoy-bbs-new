# 上线前作战清单

## 目标

这份清单用于管理 Lenjoy BBS 上线前必须完成的大块任务。它不是普通备忘录，而是上线总控表：每一项都要能判断是否完成、是否阻塞上线、产物是什么。

核心原则：

- 先冻结范围，再验证质量。
- 先修 P0/P1，再考虑优化。
- 任何影响登录、发帖、资源购买、金币、权限、后台处理的问题，都优先当作上线风险处理。
- 上线不是发布按钮结束，上线后 24 小时观察也算上线任务的一部分。

## 任务字段说明

每个任务统一按以下字段执行：

- 优先级：P0 阻塞上线，P1 建议上线前完成，P2 可上线后处理。
- 是否阻塞上线：是 / 否。
- 验收标准：一句可判断的话。
- 依赖：开始前必须先完成的任务。
- 产物：完成后要留下的记录、报告、清单或截图。

## 1. 范围冻结

- [ ] 确认本次上线必须包含的功能
  - 优先级：P0
  - 是否阻塞上线：是
  - 验收标准：形成一份明确的 V1 上线功能列表，至少覆盖注册登录、浏览、发帖、评论、点赞收藏、资源购买、金币流水、个人中心、后台基础管理。
  - 依赖：无
  - 产物：上线范围列表

- [ ] 确认本次上线暂缓的功能
  - 优先级：P0
  - 是否阻塞上线：是
  - 验收标准：所有不稳定或非核心功能都有明确处理方式，不再临时扩范围。
  - 依赖：确认上线范围
  - 产物：暂缓功能列表

- [ ] 标记高风险功能的上线策略
  - 优先级：P0
  - 是否阻塞上线：是
  - 验收标准：每个高风险功能都有处理方式：隐藏入口、标记开发中、只读、仅管理员开放或延期。
  - 依赖：确认上线范围
  - 产物：高风险功能处理表

## 2. 质量闸门

- [ ] 建立后端集成测试和测试数据库流程
  - 优先级：P0
  - 是否阻塞上线：是
  - 验收标准：后端测试可以在隔离测试数据库上稳定运行，不依赖本地脏数据。
  - 依赖：测试环境配置
  - 产物：测试运行命令、测试数据库说明、最近一次测试结果

- [ ] 跑核心功能手工测试
  - 优先级：P0
  - 是否阻塞上线：是
  - 验收标准：按 `docs/上线前手工测试用例.md` 跑完 P0 用例，失败项全部记录 BUG。
  - 依赖：测试账号、基础数据、测试环境
  - 产物：手工测试执行记录、缺陷列表

- [ ] 页面走查，确保主要页面不出错
  - 优先级：P0
  - 是否阻塞上线：是
  - 验收标准：首页、列表页、详情页、发帖页、登录注册页、个人中心、后台首页无白屏、无明显布局错乱、无关键按钮不可用。
  - 依赖：前端可运行、后端接口可用
  - 产物：页面走查记录

- [ ] 编写并运行核心功能 E2E 测试
  - 优先级：P1
  - 是否阻塞上线：核心链路失败时阻塞
  - 验收标准：至少覆盖游客浏览、登录、发帖、评论、资源购买、悬赏采纳、后台权限拦截。
  - 依赖：核心功能手工测试通过
  - 产物：E2E 测试文件、测试报告

- [ ] 权限与安全基础检查
  - 优先级：P0
  - 是否阻塞上线：是
  - 验收标准：未登录、普通用户、管理员三类身份的访问边界正确；后端接口不能只依赖前端隐藏按钮。
  - 依赖：测试账号
  - 产物：权限检查记录

- [ ] 修复后回归测试
  - 优先级：P0
  - 是否阻塞上线：是
  - 验收标准：每个 P0/P1 BUG 修复后都回归原用例，并抽查相关核心链路没有被破坏。
  - 依赖：缺陷修复
  - 产物：回归记录

## 3. 缺陷修复闸门

- [ ] 建立缺陷优先级列表
  - 优先级：P0
  - 是否阻塞上线：是
  - 验收标准：所有测试发现的问题都按 P0/P1/P2/P3 分类，且有状态和负责人。
  - 依赖：手工测试、页面走查、E2E 测试
  - 产物：缺陷列表

- [ ] 清零 P0 缺陷
  - 优先级：P0
  - 是否阻塞上线：是
  - 验收标准：不存在阻断登录、发帖、购买、金币、权限、后台处理、系统稳定性的已知问题。
  - 依赖：缺陷列表
  - 产物：P0 修复与回归记录

- [ ] 处理或明确放行 P1 缺陷
  - 优先级：P1
  - 是否阻塞上线：视影响决定
  - 验收标准：每个 P1 要么修复并回归，要么有明确绕过方案和上线后修复时间。
  - 依赖：缺陷列表
  - 产物：P1 处理决策表

- [ ] 记录 P2/P3 延后项
  - 优先级：P2
  - 是否阻塞上线：否
  - 验收标准：不影响核心闭环的问题统一记录到上线后优化池，不在上线前临时扩散。
  - 依赖：缺陷列表
  - 产物：上线后优化列表

## 4. 上线数据准备

- [ ] 准备分类、标签和帖子类型数据
  - 优先级：P0
  - 是否阻塞上线：是
  - 验收标准：前台发帖、筛选、详情展示所需的分类、标签、帖子类型数据齐全且可用。
  - 依赖：数据模型和后台管理能力
  - 产物：上线数据清单

- [ ] 准备资源来源和资源帖样例
  - 优先级：P0
  - 是否阻塞上线：是
  - 验收标准：至少有可用于真实演示和测试的资源帖样例，资源来源合法、可访问、描述清晰。
  - 依赖：资源帖发布能力、文件存储
  - 产物：资源来源记录、资源帖样例列表

- [ ] 准备初始内容或种子内容
  - 优先级：P1
  - 是否阻塞上线：建议完成
  - 验收标准：首页不是空站，至少有普通帖、资源帖、悬赏帖样例，能展示产品核心价值。
  - 依赖：分类标签、资源来源
  - 产物：初始内容清单

- [ ] 清理测试账号和敏感测试数据
  - 优先级：P0
  - 是否阻塞上线：是
  - 验收标准：生产环境不包含明显测试标题、测试用户、无效资源链接、敏感调试数据。
  - 依赖：上线数据准备完成
  - 产物：数据清理记录

- [ ] 帖子上下架能力可用
  - 优先级：P0
  - 是否阻塞上线：是
  - 验收标准：管理员下架帖子后，前台列表和详情立即不可见或显示正确状态。
  - 依赖：后台帖子管理

  - 优先级：P0
  - 是否阻塞上线：是
  - 验收标准：管理员能查看注册赠送、资源购买、资源收入、退款或后台加币相关流水。

  - 是否阻塞上线：是

  - 依赖：目标环境部署完成、上线数据准备完成
  - 产物：上线演练记录

  - 优先级：P0
  - 是否阻塞上线：是
  - 验收标准：前端 API 地址、后端服务地址、数据库、Redis、对象存储等配置指向正确环境。
  - 依赖：目标环境部署

- [ ] 数据库迁移和连接检查
  - 优先级：P0

  - 验收标准：数据库迁移已执行到最新版本，服务启动后无迁移失败和连接失败。

  - 产物：日志检查记录

- [ ] 数据库备份确认
  - 优先级：P0
  - 是否阻塞上线：是
  - 验收标准：上线前存在可追踪的数据库备份，记录备份时间、位置和负责人。
  - 依赖：数据库准备完成
  - 产物：备份记录

  - 优先级：P1
  - 是否阻塞上线：建议完成
  - 验收标准：正式开放前用少量真实账号跑一遍核心链路，确认没有环境级问题。
  - 依赖：目标环境主链路演练
  - 产物：灰度验证记录

## 7. 发布后 24 小时观察

- [ ] 观察登录和注册异常
  - 优先级：P0
  - 是否阻塞上线：发布后任务
  - 验收标准：上线后 24 小时内无持续性登录失败、注册失败或验证码异常。
  - 依赖：正式发布
  - 产物：观察记录

- [ ] 观察发帖、评论和页面错误
  - 优先级：P0
  - 是否阻塞上线：发布后任务
  - 验收标准：没有集中出现发帖失败、评论失败、页面白屏、接口 500。
  - 依赖：正式发布
  - 产物：观察记录

- [ ] 观察资源购买和钱包异常
  - 优先级：P0
  - 是否阻塞上线：发布后任务
  - 验收标准：没有重复扣费、扣费后未解锁、解锁后未扣费、流水缺失等问题。
  - 依赖：正式发布
  - 产物：资产异常观察记录

- [ ] 观察后台错误日志
  - 优先级：P0
  - 是否阻塞上线：发布后任务
  - 验收标准：后台日志没有持续性 500、数据库连接错误、对象存储错误、权限异常激增。
  - 依赖：正式发布
  - 产物：日志观察记录

- [ ] 明确回滚条件
  - 优先级：P0
  - 是否阻塞上线：是
  - 验收标准：上线前已明确哪些情况必须回滚，例如无法登录、无法发帖、购买扣费异常、后台无法处理违规内容。
  - 依赖：上线演练
  - 产物：回滚条件清单

## 8. 上线判定标准

满足以下条件才建议上线：

- P0 任务全部完成。
- P0 缺陷清零。
- P1 缺陷已修复或有明确放行说明。
- 核心手工测试通过。
- 目标环境跑通过一次完整主链路。
- 上线数据准备完成。
- 日志、备份、回滚条件已确认。

不建议上线的情况：

- 登录、发帖、购买、金币、权限任一核心链路存在已知 P0。
- 生产环境无法查看错误日志。
- 数据库没有备份。
- 管理员无法处理帖子下架或基础异常。
- 资源购买存在任何资产不一致风险。
